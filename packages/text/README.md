# @crc/text

An optional CRC package for converting shaped text into editable `PathGeometry`.
It uses a CRC-owned HarfBuzz WASM bridge, preserves quadratic/cubic curves, and
copies results into JavaScript-owned geometry. Core does not depend on this
package. Fonts have explicit `dispose()` and `Symbol.dispose` lifetimes.

See the [public API](../../docs/site/api/functions/text-geometry.md) for usage,
format support, ownership, loading, shaping options, metrics, and limits. The
[Studio example](../../packages/scenarios/src/learning/drawing/text-geometry.example.tsx)
lets users type text, generate outlines, drag points, and reset their edits.

Reference fixtures are generated by a separate native HarfBuzz harness, without
the CRC wrapper. `pnpm text:reference` regenerates them using a host C++17
compiler (`c++`, or the executable specified by `CXX`). Normal tests use the
checked-in fixture data and do not require that extra compiler.

## Contributor workflow

Use Node 24.15+ on the Node 24 LTS line and the repository's pnpm 11.21.0.
Run these commands from the repository root:

| Command                               | Purpose                                                                                          |
| ------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `pnpm text:setup`                     | Provision pinned native inputs in the ignored package cache.                                     |
| `pnpm text:doctor`                    | Check source caches, compiler version, output, and Chromium.                                     |
| `pnpm text:build`                     | Build core prerequisites, native glue/WASM, JS, and declarations.                                |
| `pnpm text:test`                      | Ensure the build and run conversion, ownership, and tooling tests.                               |
| `pnpm text:test:browser`              | Start an ephemeral Studio server and test typing, generation, dragging, and reset.               |
| `pnpm text:test:browser --production` | Exercise an existing production Studio build.                                                    |
| `pnpm test:text-package`              | Pack and install the built package outside the workspace; test Node, declarations, and Chromium. |
| `pnpm text:bench`                     | Report Node cold/warm timings for short and long text.                                           |
| `pnpm text:bench:browser`             | Report Chromium timings and verify lazy engine loading.                                          |
| `pnpm text:verify-reproducible`       | Compare two forced offline native rebuilds on the current host.                                  |
| `pnpm text:clean`                     | Remove generated outputs/native intermediates, preserving downloaded inputs.                     |

Normal dependency installation does not fetch a native SDK or compile fonts.
Published consumers receive precompiled assets. Contributor builds provision the
pinned SDK automatically; no shell activation or global toolchain changes are
needed. Python 3 and archive extraction tools must already be available. Native
scripts target macOS and Linux on arm64/x64; local execution evidence is recorded
in the [implementation plan](../../docs/superpowers/plans/2026-09-30-text-path-geometry-implementation.md).

After provisioning, `pnpm --filter @crc/text run build --offline` forbids missing
SDK/source downloads. Run `pnpm exec playwright install chromium` if browser
tests report a missing browser. Set `CRC_TEXT_STUDIO_URL` to test a running Studio
instead of creating a temporary server. Benchmarks report measurements; they do
not impose machine-dependent timing assertions.

Setup, build, and clean share a package-local lock. A timeout reports the owner
PID and lock path; remove an abandoned lock only after confirming its process
has exited. Source and host compiler archives are digest-pinned, extracted files are checked
on reuse (including compiler symlinks), and native output caches are content-checked. `dist/build-info.json`
records the native key, compiler/engine versions, compile flags, and asset hashes.
Clean staging avoids accumulating old chunks and keeps prior output until a new
build succeeds. Reproducibility checks compare output on the same host, not
across different toolchain hosts.

Font fixtures retain their licenses and source revisions/hashes. Distributed
output includes CRC, HarfBuzz, and Emscripten license notices, plus the upstream
Microsoft shaping-data, musl, and LLVM runtime notices in
`dist/THIRD-PARTY-NOTICES.txt`. Test diagnostics
are private and are not exported by `@crc/text`.

Benchmarks report uninstrumented end-to-end medians and p95 values separately
from opt-in phase measurements: input preparation, native setup, shaping, outline
extraction, bulk buffer-view creation, path/metadata construction, and bounds.
The buffer-view phase creates views rather than copying output; materialization
performs the copy into independently owned geometry. Instrumentation changes
timing and separate phase medians need not sum to the end-to-end median.
Chromium clock precision can round small phases to zero; this means below
measurement resolution, not free work. Asset reports list every emitted runtime
file plus a browser distribution upper bound, excluding core and font bytes.

The wrapper bounds native shaping-plan retention to 64 distinct configurations
per font. At that boundary it renews the internal face while sharing the font
blob; the public font stays valid and further configurations remain accepted.
This bounds cache lookup work as well as retained plans. The shared engine also
limits interned explicit language tags as documented in the public API.

After building, narrow the Node suite with
`pnpm --filter @crc/text test --test-name-pattern="kerning"`. The runner places
Node test options before the test paths so pnpm argument forwarding preserves
the requested filter.
