# First collection briefs

These twelve candidates make the broader idea bank concrete. They are a proposed editorial collection, not an approved implementation queue. Start by testing three representative briefs: Spring switch, Native slider and living ink, and the Kinetic studio desk storyboard. Complete and evaluate their smallest runnable versions before expanding the collection.

The table defines a teaching contract, a hands-on action, an edit prompt, a screenshot, and a scope boundary. The tiny companions of the showcase are complete independent examples, not fragments that require the showcase infrastructure.

## Focused starting points

### Spring switch

Idea E001. Lesson: one target signal drives a spring transition. The visitor activates a visibly tactile switch, then changes the spring configuration and feels the difference. Target 30–60 meaningful lines; avoid building a settings panel. Screenshot a clear settled state, not an ambiguous mid-animation frame. Prove keyboard activation as well as pointer use. This establishes the quality bar for the smallest examples.

### Spotlight reveal

Idea E003. Lesson: a moving clip reveals part of a second composition. The visitor moves a spotlight over a poster, then changes the aperture size. Target 40–80 meaningful lines. Use a simple local illustration so asset loading does not dominate. Screenshot an aperture that visibly reveals contrasting content. Keep complex filter stacks and gesture recognition out of this lesson.

### Particle stamp

Idea E009. Lesson: a discrete interaction triggers a bounded particle effect. The visitor activates one stamp, then changes the burst palette or count. Target 40–80 meaningful lines, with particle descriptors visible. Capture a repeatable moment in the burst. Avoid an emitter configuration dashboard; that can become a separate showcase.

### Sleepy robot

Idea E063. Lesson: one state change controls a charming reusable character. The visitor wakes the robot, then changes a motion duration or expression value. Target 50–100 meaningful lines. Use a few deliberate shapes rather than a complex illustration engine. Capture a recognizable expression. Keep focus and activation feedback clear without teaching the entire focus API here.

## HTML and data starting points

### Native slider and living ink

Idea E011. Lesson: native input changes a signal consumed by a Canvas texture. The visitor changes one parameter and sees the pattern respond, then changes the parameter range. Target 60–100 meaningful lines plus explicitly shown host setup if required. Capture both real HTML and Canvas. Use the current HtmlBox or page-owned HTML boundary deliberately, with a short explanation of which owns what. Do not filter a group enclosing HTML.

### Editable name badge

Idea E012. Lesson: native text editing feeds a Canvas presentation. The visitor types a name, then changes one visual property of the badge. Target 50–90 meaningful lines with a small maximum text length or explicitly handled overflow. Screenshot a short readable name. Teach the native-input bridge, not a Canvas text editor.

### One line and one hover marker

Idea E041. Lesson: a scale and inspection rule turn pointer position into a readable value. The visitor inspects three data points, then changes one data value. Target 60–100 meaningful lines where practical; explain any extra setup instead of hiding it. Capture a selected point with readable axes and a tooltip. Keep multiple series, comparison modes, and diagnostic tables out of this version.

### Timeline scrubber

Idea E032. Lesson: a native range control seeks an animation program. The visitor scrubs a short composition, then changes one track's duration. Target one program and one meaningful transition. Capture an intermediate position with the native control visible. Explain ownership of playback commands; avoid a timeline editor, transport skin, and nested program catalog.

## Composition starting points

### Stack the stones

Idea E023. Lesson: a few 2D bodies respond to direct user manipulation. The visitor moves one stone and resets the scene, then changes one material/body property. Keep the scene to a few bodies and one drag behavior. Capture an attractive stable stack. A technical spike should verify the supported dragging path before promising a small code budget; do not sneak in an interaction framework.

### Stir existing ink

Idea E072. Lesson: pointer movement sends displacement to a living texture. The visitor pauses reaction and stirs to isolate movement, then changes brush radius. Keep the coordinate conversion adjacent to the message. Capture a clear swirl at a deterministic scripted state. Explain that this is pattern transport, not a fluid simulation. Use the current Stirred Ink example as extraction input, not as the required final structure.

### Three scene with CRC controls

Idea E081. Lesson: one persistent Three scene participates in a CRC composition. The visitor changes a simple object's presentation with a CRC control, then changes one ordinary Three material property. Use primitives so loaders and asset licensing do not bury the adapter. Show create/update/dispose ownership in the source. Screenshot the object and surrounding Canvas controls. This may exceed focused-example budgets; label the necessary integration setup honestly.

## Signature showcase

### Kinetic studio desk

Idea E091. Lesson: the supported boundaries compose into a complete expressive application. Combine a physics-driven ink gesture, a native control card, and a small Three artifact. Start with the ink gesture, then add the other regions only when the composition remains clear.

No line limit; use a few readable files divided by visible responsibility. Screenshot the complete browser composition. Provide a short map of HTML, Canvas, physics, textures, and Three ownership, plus links to independently runnable small examples. Include a pause state, reduced-motion presentation, and a useful fallback when the external renderer cannot run.

The homepage may use an adapted presentation of this showcase. It must not quietly require a separate incompatible implementation. Decide what is shared after the scene earns its place through hands-on feedback.
